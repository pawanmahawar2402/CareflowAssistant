# CareFlow — AI Care Coordination Assistant

**Applied AI Professional Certification Program · IIT Hyderabad**
**Problem Statement 1 · Healthcare Operations**

A multi-agent assistant for a multi-specialty clinic. It answers insurance and policy questions from clinic
documents, looks up referrals and eligibility, remembers each patient's preferences and recent requests, and
hands clinical or emergent matters to human staff. It is built as a LangGraph workflow with a deterministic
supervisor, specialist agents, MCP tool access, Redis memory and a Qdrant vector index.

**Start here:** [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — components, design decisions, evaluation summary,
guardrail coverage, known gaps and deployment steps.

## Milestones

| # | What is built | Where |
|---|---|---|
| M1 | Typed intake (`PatientRequest`), one provider-agnostic LLM layer, validated output with repair loop | `careflow/m1_intake`, `careflow/llm.py` |
| M2 | Tool-using agent; EHR, eligibility, co-pay, booking and referral tools with business limits in code | `careflow/m2_agent` |
| M3 | Four memory types on Redis (working, episodic, semantic, procedural); per-user namespaces; privacy delete | `careflow/m3_memory` |
| M4 | Hybrid retrieval (dense + BM25, fused, reranked); grounded, cited answers; retrieval evaluation | `careflow/m4_rag` |
| M5 | LangGraph workflow; SQLite checkpoints; human approval before escalation | `careflow/m5_workflow` |
| M6 | Specialist team with enforced boundaries; MCP server and client for domain systems | `careflow/m6_agents` |
| M7 | Circuit breaker, retries with backoff, fallback model, tracing hooks, KPI log, failure-injection harness | `careflow/m7_observability` |
| M8 | Guardrails in code, golden sets, FastAPI service with HTTP 422 on guardrail refusals, probes, UI, evaluation dashboard | `careflow/m8_service` |

## Quick start

Requires Python 3.12, Docker (for Redis and Qdrant) and a Gemini API key.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.lock.txt            # pinned versions
cp .env.example .env                            # then add your GEMINI_API_KEY
docker run -d -p 6379:6379 redis:7-alpine       # memory store
docker run -d -p 6333:6333 qdrant/qdrant        # vector index
python generate_data.py                         # synthetic tables, corpus, golden sets
python -m careflow.m4_rag.ingest                # index the policy corpus
uvicorn careflow.m8_service.api:app --port 8010 # then open http://localhost:8010/ui/
```

If port 8010 is busy, pick another port and use it in the URL.

## Running the evaluations

Each command writes its result file to `eval_results/`.

```bash
python -m careflow.m4_rag.retrieval_eval        # retrieval: dense vs hybrid vs hybrid_rerank (no LLM calls beyond embeddings)
python -m careflow.m8_service.eval_runner       # 24-case end-to-end golden set (uses the model)
python -m careflow.m8_service.probes            # adversarial probes P1, P2, P3, P5 (no LLM)
python -m careflow.m7_observability.fault_harness   # seeded failure injection (stub model, no quota)
PYTHON=.venv/bin/python scripts/restart_test.sh     # kill -9 restart test against the real server
python -m pytest tests/                         # unit, workflow and memory tests
```

Single end-to-end cases can be rerun with `EVAL_IDS=e04,e11 python -m careflow.m8_service.eval_runner`.

## Repository layout

```
careflow/          application package (one folder per milestone, plus config, llm and the eval runners)
data/              synthetic tables, policy corpus and golden sets (generated by generate_data.py)
docs/              ARCHITECTURE.md
eval_results/      committed evaluation outputs (retrieval, end-to-end, probes, fault injection, restart test)
scripts/           kill-and-restart test and its stub launcher
tests/             offline, workflow, memory and citation tests
```

## Tests

`python -m pytest tests/` runs 30 tests. The LLM is stubbed in the workflow tests, so they use no quota.
Redis-backed tests are skipped automatically if Redis is not running, and the workflow tests need the MCP
server, which starts as a subprocess.

## Configuration

Every model name, provider URL, threshold and limit is defined once in `careflow/config.py` and can be
overridden in `.env`. Switching the LLM provider needs only `CAREFLOW_LLM_MODEL` and the matching API key.

## API examples

These run against the server started above (`http://localhost:8010`).

```bash
# health and circuit state
curl -s localhost:8010/health

# eligibility (answered through the EHR tools over MCP)
curl -s -XPOST localhost:8010/chat -H 'content-type: application/json' \
  -d '{"message":"Is insurance ID MRD-100037 active?","session_id":"demo-1","user_id":"pt-demo-01"}'

# policy question (answered from the clinic documents, with citations)
curl -s -XPOST localhost:8010/chat -H 'content-type: application/json' \
  -d '{"message":"What is the specialist co-pay on the Silver plan?","session_id":"demo-2"}'

# guardrail refusal: HTTP 422 with the reason and the flags
curl -s -i -XPOST localhost:8010/chat -H 'content-type: application/json' \
  -d '{"message":"What dose of ibuprofen should I take?","session_id":"demo-3"}'

# emergency: the case pauses for staff (route human_review, pending_human true)
curl -s -XPOST localhost:8010/chat -H 'content-type: application/json' \
  -d '{"message":"I have crushing chest pain","session_id":"demo-4"}'

# staff decision on the paused case
curl -s -XPOST localhost:8010/review -H 'content-type: application/json' \
  -d '{"session_id":"demo-4","approved":true,"note":"confirmed by nurse"}'

# privacy: delete one patient's episodic and semantic memory
curl -s -XDELETE localhost:8010/users/pt-demo-01/memory

# committed evaluation outputs, as used by the dashboard
curl -s localhost:8010/eval/results | head -c 300
```
